# 知识库工具说明

## 环境与输入

`资料库.py` 使用已有 Python 3.10 以上与标准库，Git 只用于统计历史大小，不访问互联网、不下载附件、不自动安装依赖。默认仓库为脚本所在目录的上级，可用 `--root` 指定独立仓库。

输入为 元件/、网站/ 的 JSON 与必需的 docs/分类规则.json，模板只供填写；输出为终端结果、派生索引和可选的本地 JSON 报告。分类词表结构及扩充流程见[分类规则](../docs/分类规则.md)。

## 命令

```text
python scripts/资料库.py check
python scripts/资料库.py check --report 本地/检查报告.json
python scripts/资料库.py index --write
python scripts/资料库.py search "三档光开关"
python scripts/资料库.py search "INA219EVM" --all-statuses --json
python -X utf8 -m unittest discover -s scripts -p "test_*.py" -v
```

`check` 只读检查，失败返回非零退出码；`--report` 仅允许 本地/ 中尚不存在的 JSON 路径，拒绝覆盖。`index` 默认只比较索引是否最新；显式 `--write` 才用原子替换生成的索引，不覆盖元件或网站事实文件。`search` 返回最多 5 项，完整型号优先，再按名称、别名、品牌和分类匹配；无结果返回空结果说明。

## 验证范围

检查必填字段、状态、日期、来源网址、型号与硬件版本身份重复、记录编号重复、附件路径及哈希、公开分发依据、可读性标记、重复附件、CAD与压缩包、伪装的常见二进制格式、明显网格JSON字段、嵌入图片编码、机器绝对路径以及部分凭证特征。

分类名称必须登记在 docs/分类规则.json，各类具有非空定义和边界；词表缺失、空白、格式错误、同名或含路径的分类名称都会导致失败，不能使用默认词表代替。正式元件路径严格为 `元件/分类/资料编号.json`，目录与分类字段一致，文件名与资料编号一致，不允许额外层级或大写扩展名。检查、索引生成和检索共用这些约束，失败时不替换原有索引。

图片单个 300 KiB、PDF 单个 2 MiB、文本单个 1 MiB、工作文件合计 100 MiB；Git 历史对象另行报告。扫描正式工作目录时包括尚未跟踪或被忽略的CAD，不因 .gitignore 忽略就视为合格。本地/、.local/、.git/、虚拟环境和 Python 缓存按约定排除；排除区域仍不属于可发布资料。

工具不检查远程链接是否仍在线、不自动判断附件版权或物理用途分类、不做OCR或图纸视觉判断、不验证电气适配、不证明全部历史会话已经回收。显式的人工核对字段是执行记录，不能由脚本自动生成真实核对事实。

## 维护与保护

事实 JSON 是唯一数据源，索引可重建。修改规则时同步本说明、docs/收录规范.md、docs/资料字段说明.md 与 docs/apps-code-map.md。测试使用临时目录，隔离真实资料；不写入来源项目或自动提交推送。
