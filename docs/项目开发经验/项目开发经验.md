# 项目开发经验

## 资料体积与身份

文件扩展名不能代表体积或用途：现有资料中既有大型 CAD，也有转换网格 JSON。收录应同时检查允许的资料类型、实际字节数、附件指纹和来源，而不是允许全部 JSON 或把大文件压缩后入库。

CAD 不纳入附件白名单，官方获取网址可指向 CAD 或压缩包。不要把“允许记录下载地址”误解为“允许提交下载内容”。

## 核对与回收

同型号的新旧硬件版本可能有不同板型，系列图纸标题栏也可能出现其他型号。完整品牌、型号、硬件版本应共同确定身份，保留实际采用依据和已排除来源。

已有项目可读的原件不等于可公开再分发，也不等于原网站当前仍可访问。初始化先收录链接和自行整理的摘要，分别记录原核对日期、回收日期及核对方式。

## 分类与路径约束

只校验JSON中的分类、编号字段不足以保证目录规范。例如连接器记录放入开关目录，或文件名与资料编号不同，都可能通过纯字段检查。应由同一分类词表约束字段，并同时比较仓库相对路径的层级、分类目录及文件名。

分类词表是运行所需规范；缺失或无效时应报告失败，不回退到另一份硬编码分类。索引生成与检索共用检查入口，避免检查拒绝错放资料而另一条命令仍接纳。失败不能覆盖原有索引，也不自动移动或改名用户资料。
