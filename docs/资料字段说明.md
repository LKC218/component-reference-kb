# 资料字段说明

## 元件记录

每个 JSON 文件是一份元件记录，放在 元件/分类/资料编号.json。字段以 模板/元件资料.json 为准，未知事项写明未知，不留伪造事实。

分类必须登记在[分类规则JSON](分类规则.json)，与直接父目录名称完全一致；资料编号必须与文件名主体完全一致，扩展名为小写 `.json`，不允许省略分类层或增加额外层级。定义与新增分类流程见[分类规则](分类规则.md)。

| 字段 | 要求 |
| --- | --- |
| 架构版本、资料编号 | 当前版本为 1；编号由字母数字与连字符组成，仓库唯一 |
| 名称、品牌、型号、硬件版本、分类 | 必填；身份按品牌、型号、硬件版本比较，不以课程编号合并 |
| 别名、关联课程 | 字符串数组，供口语搜索与课程关联 |
| 核对状态、核对日期、核对依据 | 状态为已核实、待核实、已排除；日期为 YYYY-MM-DD；依据写清证据性质 |
| 核对范围、限制 | 字符串数组；说明结论在哪些范围成立，缺失或冲突是什么 |
| 来源 | 来源对象数组，至少一条 |
| 出处 | 回收记录数组，至少一条；会话编号、项目标识、项目相对路径、回收日期 |

## 来源对象

每条来源必填 类型、标题、网址、状态、核对方式、核对日期、说明。类型限定为“元件网站”“实拍”“图纸”“CAD获取地址”；核对方式限定为“本地资料回收”“在线核对”。

可选 定位、格式、访问要求、原件指纹、附件。定位保存页码、图号或对应型号行。原件指纹只含 字节数 和 SHA256，描述实际已获取的原始文件，不意味着本仓库保存了它。

附件对象包含 路径、字节数、SHA256、公开分发依据、可读性已核对。路径必须在 附件/ 内，以仓库相对路径表示；分发依据应能追溯到具体授权或公开许可。CAD获取地址不得带附件对象。图片格式仅限 PNG、JPEG、WebP；图纸还支持 PDF。

## 网站记录

放在 网站/名称.json，字段为 架构版本、名称、网址、适用资料类型、搜索建议、访问说明、核对日期、核对方式。网址使用网站根入口；搜索建议可写先完整型号、再官方型号页，不承诺本轮重新验证网站功能。

## 派生索引

索引/资料索引.json 只包含身份、分类、别名、状态与记录路径，不重复维护尺寸或证据正文。使用 `python scripts/资料库.py index --write` 自动生成。修改事实后检查会提示索引过期。

## 模板与本地数据

模板中的“待填写”等内容不是正式资料，不能直接复制进入 元件/。候选保存在 本地/待整理/会话编号/；机器配置、完整原件及报告都不进入索引。
