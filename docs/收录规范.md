# 元件资料收录规范

## 范围与身份

只收录元件网站、实拍、图纸、CAD 获取地址。完整品牌、型号、硬件版本共同区分元件。型号未知、硬件版本无法对应或只有同系列参考时记录为待核实，不自动补造事实。课程编号与发现会话只是关联信息。

本知识库维护脚本属于工具基础设施；不收录元件建模脚本、模型工程、转换网格及 Blender、Three.js 等方法资料。

分类以[分类规则JSON](分类规则.json)为唯一词表，定义、边界和扩充流程见[分类规则](分类规则.md)。正式元件记录只允许 `元件/分类/资料编号.json` 三层路径，分类字段必须等于目录名称，文件名必须等于资料编号加小写 `.json`；不得另建同义分类或增加版本子目录。网站记录只允许 `网站/名称.json` 两层路径，文件名必须等于“名称”字段加小写 `.json`，名称需能作为单层文件名。

## 状态与核对方式

| 状态 | 含义 |
| --- | --- |
| 已核实 | 在核对范围内已有明确依据；不扩展为制造、电气或模型验收结论 |
| 待核实 | 缺少来源、对应关系、版本、背面或尺寸依据，保留缺失原因 |
| 已排除 | 已发现不适用，保留原始来源和排除原因，避免反复检索 |

状态同时作用于元件和每条来源。来源核对方式为“本地资料回收”或“在线核对”。回收日期和来源原来的核对日期分别保存；本地文件今天可读不代表远程链接今天仍可下载。仅搜索摘要可见时，必须明确写在核对说明，不等同完整网页核对。

## 来源与文件

每条来源必须有完整网址、类型、标题、核对方式及日期、适用说明。PDF 尽量写明文件修订版与页码或图号。CAD 记录获取页面、格式及访问要求，不上传本体或压缩包。

原件指纹描述此前实际获得的文件，可以在没有本地附件时保留；附件指纹描述本仓库内的实际文件。两者不得混用。只对实际文件计算 SHA256，不根据网页、文件名或他人摘要编造哈希。

公开附件需要明确的公开分发依据与可读性核对。未确认时只保存来源地址和自行撰写的摘要，不自动复制已有项目的原件。实拍、尺寸图及系列外形图分别说明用途；不得从示意图推断真实尺寸。

## 空间预算

| 内容 | 上限与处理 |
| --- | --- |
| 实拍与尺寸图附件 | 单张 307200 字节，即 300 KiB；尺寸数字必须清晰 |
| PDF 附件 | 单个 2097152 字节，即 2 MiB；保留必要完整原件，不批量导出每页图片 |
| 文本与 JSON | 单个 1048576 字节，即 1 MiB；不嵌入图片编码、整页HTML或网格数组 |
| 工作文件合计 | 104857600 字节，即 100 MiB；超限停止，不自动删除或压缩原件 |
| Git 历史对象 | 单独统计；超过 100 MiB 提示后续人工评估，删除工作文件不代表历史已缩小 |

同字节附件只保存一份，其他元件通过相同相对路径引用。不同大小的预览副本不是同一字节文件，需要另记原件关系。附件统一放 附件/，不以改扩展名或压缩包规避预算。不启用 Git LFS。

## 多会话与更新

每个会话先把候选保存在被忽略的 本地/待整理/会话编号/，用资料模板填写。候选不代表已经进入正式知识库，也不会随 Git 推送。

由一个整合会话检查已有资料后修改 元件/ 和 网站/。相同型号不同硬件版本各存一份；同一版本的来源新增并保留出处；互相矛盾的来源保持独立并说明冲突，不自动选择一个覆盖另一个。来源会话至少记录会话编号或可追溯的任务标识、项目标识、项目相对路径和回收日期。

正式文件写完后生成索引、运行检查并报告新增、更新、已排除、冲突、缺失及字节变化。检查不访问互联网，不判定图片视觉准确性；实际在线核验与人工阅图另行记录。工具只覆盖文件格式、约定字段、部分敏感信息特征及体积约束，不替代人工内容审核。

## 发布与可访问性

读取仓库不需要把全部资料一次交给 AI；先读索引与命中的资料卡，再按需访问原文。远端智能体不能依赖本机盘符路径，正式记录只能使用仓库相对路径和公开或获授权的稳定网址。

不保存凭证、带访问令牌的网址、临时签名地址或用户完整聊天。不自动提交、推送、删除旧记录、安装软件、修改其他项目配置。获得明确发布授权后，也只处理本次知识库文件。
